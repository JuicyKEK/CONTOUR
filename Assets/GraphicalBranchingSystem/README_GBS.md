# GBS — Graphical Branching System

Визуальный однонаправленный граф сюжета для Unity. Заменяет ручную сборку цепочек `StoryNodeSO`
в инспекторе: логика входа в ноду и условия переходов теперь живут прямо в нодах графа.

 Подробные руководства:
- `Documentation/GBS_MANUAL_RU.md` — полная инструкция на русском (все поля нод, все SO из `Assets/Story`, рецепты, траблшутинг)
- `Documentation/GBS_MANUAL_EN.md` — the same manual in English

## Структура

```
Scripts/Runtime/Data     — сериализуемая модель графа (GBSGraphSO, ноды, связи)
Scripts/Runtime/Core     — исполнение графа (GBSGraphRunner, GBSBoolEvaluator, GBSStarter)
Scripts/Runtime/Save     — игровые сейвы прогресса (GBSSaveSystem)
Scripts/Editor           — окно графа, ноды редактора, сохранение/загрузка графа, импортер Story
```

## Типы нод

| Нода | Порты | Назначение |
|------|-------|------------|
| **Start** | вход `Start If` (bool), выход `Out` (flow) | Точка входа. Порт свободен → граф стартует сразу. Порт занят → граф ждёт, пока выражение станет истинным |
| **Story** | вход `In` (flow), на каждое условие перехода: `If` (bool) + выход (flow) | События `GBSEvent` + `StoryAction` при входе, затем проверка условий перехода |
| **End** | вход `In` (flow) | Граф помечается пройденным, поднимает список `GBSEvent` |
| **Condition** | выход `Value` (bool) | Обёртка над `StoryCondition` SO. Сработав, «защёлкивается» (остаётся `true`) |
| **Boolean Operation** | N входов (bool), выход `Value` (bool) | AND / OR / NOT / NAND / NOR / XOR / XNOR. Кнопки `+` / `-` меняют число входов |
| **Graph Completed** | вход `In` (flow), выходы `Out` (flow) и `Value` (bool) | Ждёт завершения указанного графа. Можно использовать как условие (порт `Value`) **и** как ожидание прямо внутри потока сюжета (flow `In` → `Out`) |

Flow-порты можно соединять только с flow-портами, bool — только с bool.

## Как работает Story-нода

1. Вход в ноду → поднимаются все `GBSEvent` из `On Enter Events`.
2. Последовательно (с await) выполняются все `StoryAction` из `On Enter Actions`.
3. Нода начинает проверять свои **условия перехода**:
   - если какое-то условие уже выполнено на момент проверки — переход происходит сразу;
   - иначе все условия ждут параллельно, побеждает выполнившееся первым (остальные отменяются).
4. Сюжет уходит **по ребру, выходящему из победившего условия**.

Каждое условие перехода — это строка в ноде: `If` (булев вход) · имя · `StoryCondition` (SO) · `X` · выходной flow-порт.
Источник условия: подключённый порт `If` (приоритет) → поле `StoryCondition` → если пусто, условие срабатывает мгновенно (ветка «по умолчанию»).
Кнопка `Add Transition` добавляет условие, `X` — удаляет вместе с портами и рёбрами.
Списки `On Enter Events` / `On Enter Actions` тоже добавляются и удаляются кнопками `Add ...` / `X`.

## Работа в редакторе

1. `UnityDev → GBS → Open Graph`.
2. Правый клик по полотну (или пробел) → создание нод.
3. У Story-ноды: `Add Transition` добавляет условие перехода; в строке задаётся имя,
   `StoryCondition` (SO) и/или подключается булев порт `If`; из строки тянется ребро
   к следующей ноде. `X` удаляет условие.
4. В футере Story-ноды: `On Enter Events` (GBSEvent) и `On Enter Actions` (StoryAction) —
   у каждого элемента есть кнопка `X` для удаления.
5. Тулбар:
   - `File Name:` — имя ассета графа;
   - `Graph:` — ассет, в который сохраняем/из которого грузим;
   - `Save` — сохраняет граф в `Assets/GraphicalBranchingSystem/Graphs/<File Name>.asset`
     (если имя отличается от текущего ассета — создаётся новый граф);
   - `Load` — загружает выбранный ассет в окно;
   - `New` — чистое полотно;
   - `Clear Saves` — удалить игровой сейв прогресса.
6. Двойной клик по ассету `GBSGraphSO` открывает его в окне графа.

## Сцена

1. Повесить `GBSStarter` на объект сцены (он `[JDIMonoController]`, зависимости приходят через JuicyDI).
2. В `Graphs` положить нужные ассеты графов: большой сюжет + микро-сюжеты.
3. `Load On Start` — грузить прогресс при старте, `Auto Save On Node Enter` — автосейв на каждой ноде.

Все графы запускаются одновременно; те, у кого Start-нода ждёт условие
(например `Graph Completed` другого графа), стартуют сами, когда условие выполнится.

## Сейвы

- Файл: `Application.persistentDataPath/gbs_story_save.json`.
- Сохраняются: текущая нода каждого графа, флаг завершённости, защёлкнутые условия и флаги blackboard.
- API: `GBSStarter.SaveProgress()`, `GBSStarter.LoadProgress()`, `GBSStarter.ClearProgress()`
  (доступны и через контекстное меню компонента).
- Из редактора: `UnityDev → GBS → Saves → Clear Saves` / `Show Save Path`.

## Миграция со старого Story

Выделить стартовую `StoryNodeSO` и вызвать `UnityDev → GBS → Import Story From StoryNodeSO`:
цепочка нод превратится в граф с автоматической расстановкой, Start- и End-нодами.
`StoryAction` / `StoryCondition` ассеты переиспользуются как есть.
